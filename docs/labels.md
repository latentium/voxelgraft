# 標識の解説

VoxelGraft の設計および実装の考察で用いた標識を整理したもの。
各項目の状態は、次の語で示す。

| 状態 | 定義 |
|---|---|
| 完了 | 実装または実験を終え、結論を得たもの |
| 部分実装 | 一部のみ実装したもの。残りは拡張の段階で扱う |
| 暫定 | 実装済みであるが、比較の後に再決定するもの |
| 未着手 | 着手していないもの |
| 未決定 | 決定の方法が定まっていないもの |

## X：実験

### X1：終了の検出 — 完了

- 問い：世界に投入した vesicle がすべて行き着いたことを、いかに検出するか
- 比較した方式：
  - count：投入数 ＋ 組み立て数 ＝ 到着数 ＋ 廃棄数 ＋ 保持数 ＋ 組み立てへの使用数
  - quiescence：すべての管およびストックの停止
  - promise：管およびストックの停止を Promise により通知し、集約する
- 結果：
  - count は、出口が詰まる組み立ての場面において、1ms 間隔の確認で 200 回中 36 回、早期の誤検出を生じた
  - quiescence および promise の早期の誤検出は 0 回
  - 検出が約 1.5 秒遅延する回がまれに生じた。イベントループの間隔も同程度に空いていたことから、プロセスの一時停止によるものと推定される。結果の正しさは保たれていた
- 結論：quiescence を採用する（src/cell/ext_completion.ts の `byQuiescence`）
- 備考：比較に用いた場面のコードは、本リポジトリには含めていない

### X2：組み方の節からの世界の構築 — 部分実装

- 問い：DSL の組み方の節から構築した世界が、手作業で構築した世界と同一の結果を与えるか
- 現状：世界の形は固定（src/world.ts）。組み方の節は、検査および書き出しの選択のみ
- 残課題：セルの木そのものを組み方の節で記述可能とするか

- 関連する実装：I7

### X4：格子の大きさと段の処理時間 — 未着手

- 関連する実装：I4、I5、I6

### X5：同一 DSL に対する結果の同一性 — 未着手

- 問い：同一の DSL を繰り返し実行したとき、結果は同一となるか
- 保留中の課題：管の時間切れは時刻の差により判定する。このため、プロセスの一時停止により、誤った時間切れによる廃棄が生じうる
- 現状の扱い：段をすべて同期とし、同一の子を並べず、管の時間切れを事実上無効とする（src/world.ts）

### X6：HTML の構成 — 未着手（1 ファイル・自前の描画を暫定採用）

- 問い：1 ファイルで足りるか。外部ライブラリを用いるか。画像とするか
- 観察事項：面の境界に細い白線が生じる。canvas が多角形の縁を平滑化することによるものと推定される
- 関連する実装：I6

### X7：help のみによる DSL の記述 — 未着手

- 関連する実装：I8。SKILL.md は help を差し込むため、X7 の結果は Skill として渡る内容にそのまま及ぶ

### X8：版の保存と復元 — 未着手

- 問い：save → 修正 → save → restore の過程で、版の状態およびハッシュが正しく記録されるか
- 関連する実装：I9、I10。M3 と併せて実施する

### X9：HTML からの DSL の復元 — 完了

- 問い：書き出した HTML から DSL を復元できるか。復元した DSL は、元と同一のボクセルを与えるか
- 前提：HTML には描画用の data（name、size、materials、colors、voxels、partVoxels）を埋め込む（src/html.ts）
- 比較した形：
  - 形 a：Part 一つ、ボクセル 1 個ずつの fill
  - 形 b：材質ごとの Part、同一材質の隣接ボクセルを箱へ集約（欲張り法）
- 結果：
  - calico_cat（918 個）、calico_cat_hd（6580 個）とも、形 a・形 b の双方で名、大きさ、ボクセルの集まりが一致
  - 操作の数：元 28 / 51、形 a 918 / 6580、形 b 54 / 89
  - 復元不能なもの：Part の分け方、操作の並び、Part 間の上書きの順、未使用の palette、assembly の節
- 結論：形は復元可能。DSL の構造は復元不能
- 残課題：partVoxels の名と数を手がかりとした Part の推定（答えが一意に定まらない）
- 所在：experiments/restore/

## G：初期構想との差異

初期構想（叩き台）：Interaction Cell、Agent Cell 等をすべてセルとして持つ、単一のアプリケーションの形。
その後の決定による各要素の扱いは、次のとおり。

| 標識 | 初期構想 | 扱い |
|---|---|---|
| G1 | Interaction Cell（Chat、3D Viewport、Manual Editor） | 対話は Claude Code で行う。HTML は閲覧専用とする。手動の編集は、人間が DSL を直接修正する |
| G2 | Agent Cell（意図の解釈、Skill の選択、計画） | Claude Code そのものが担う。セルの世界の外に位置する |
| G3 | Undo / Redo、変更履歴 | 版の全体保存による（M3） |
| G4 | Voxel Engine の決定論性 | 段の純粋性により支える。到着順の揺らぎは、結果を asset.parts の順に整列することで扱う。時間切れは X5 で扱う |
| G5 | 操作命令（AddVoxel、FillRegion 等） | DSL の parts における操作。現状は fill / remove |
| G6 | Part ごとの ID、所属、依存 | 部品番号を Part の名とする。StockOrganelle により組み立て、荷札に合流の世代を残す |
| G7 | 役割のまとまりを「Cell」と呼ぶこと | 未決定。コード上の Cell（照合して振り分けるクラス）と名称が重なる |
